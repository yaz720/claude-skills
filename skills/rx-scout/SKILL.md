# RxScout — 问药

## 概述

本技能把「该用什么药」这个问题变成一份系统化的选药调研报告。核心方法是**一个筛选引擎,跑在用药决策漏斗的不同层级**:

```
病症(如高血压)
   ↓ 选类:这个病症有哪几大类药,各有什么特点,我的情况适合哪类
药物类别(如 ARB 类 / 他汀类)
   ↓ 类内选药:类内成员逐个对比,选出最适合的
具体药物(如 匹伐他汀)
   ↓ 剂量与联用:最低有效剂量起步,不够时联用什么
具体方案
```

选类和类内选药用的是**同一套引擎**,只是「成员」从药换成了类。技能启动时先定位用户在漏斗的哪一层,从那里开始往下跑。

**产出物的定位(最重要的一条)**:本技能输出的是**调研功课与就诊讨论材料,不是处方,不是医疗建议**。任何开始用药、停药、换药、调整剂量的决定都必须由用户的医生做出。报告的价值在于让用户带着系统化的信息和高质量的问题去见医生,而不是替代医生。

## 四个进入场景

根据用户已知的信息定位进入层级,不要问用户"你在哪个场景",从对话内容自己判断:

- **场景一:只知道病症**("我要降压,该吃什么药")。先跑**选类层**:该病症的主要药物类别全员盘点+画像匹配,做到指南级即可(类的特点、一线地位、适用人群)。选定 1-2 个候选类后,可以附一段**简短类内速览**(每个成员一两行,点出定位与显著差异),帮读者对下一步有感;但不要对成员跑完整引擎,也不要在本轮给出成员级的最终推荐——把"下一步可做类内选药"明确指出来,留给单独一轮。这样单轮报告保持可读的篇幅,类内的深度调研在真正进入那一层时再做足。
- **场景二:已知类别**("七种他汀选哪个")。直接跑**类内层**,这是本技能的核心场景,做全做深。
- **场景三:医生已给了几个具体方案**("医生说 A 或 B 都行,帮我比比")。候选集已固定,跳过全员盘点,直接做维度对比+逐条需求匹配+就诊问题清单。但要补一句全景说明:这几个候选在整个类别里处于什么位置,有没有明显被漏掉的选项值得带去问医生。
- **场景四:已在用药,评估调整**("现在吃 X 药 4mg,要不要减量/换药")。以现状为锚点:当前药物的响应情况、剂量在该药谱系中的位置、族裔暴露因素、减量/联用/换药各自的证据,产出供医生讨论的调整选项,**绝不直接建议用户自行调整**。

## 第一步:理解需求与画像

从当前对话和用户消息中提取:调研对象(病症/类别/具体候选)、进入场景、使用者画像。画像要素:年龄段、性别、族裔(对药代动力学权重很高,见引擎第五步)、相关诊断与关键指标(如 LDL、血压值)、合并症、正在用的所有药物与补充剂、既往的药物不耐受、用户的诉求排序(如"最怕肝损伤,肌肉症状可以排后")。

- 信息充分:2-3 句话向用户复述画像确认,不用逐项问卷。
- 信息不足:一次性引导补充("可以说说使用者的年龄、正在用的其他药、最在意避免哪类副作用"),只引导一次,用户给多少用多少。
- 完全没有画像:做**通用对比报告**(模式B),按人群分述差异,末尾提示"给出个人情况可出针对性版本"。

## 筛选引擎(七步,漏斗每一层通用)

### 1. 全员盘点

列出该层级的**全部**成员:类内选药时是该类全部已批准药物(以 FDA 批准为基准,重要的他国上市成员注明),选类时是该病症的全部主要药物类别。附批准时间线,**撤市成员也要列**并说明撤市原因——撤市史本身是这类药风险谱的重要信息。

为什么这步必须做:模型裸答只会提最流行的两三种,而最适合特定画像的常常不是最流行的(母版案例:匹伐他汀不是市场主流,却是东亚画像下的第一选择)。盘点完整性要与权威清单核对(FDA 网站、权威综述),不确定完整时明说。

### 2. 固定五维横向对比

| 维度 | 覆盖内容 |
|---|---|
| 效力 | 强度分级、等效剂量换算(如 匹伐他汀 4mg ≈ 阿托伐他汀 20-30mg) |
| 代谢与相互作用 | 代谢通路(如 CYP3A4/CYP2C9/不经 CYP450)、食物禁忌、与常见联用药的冲突 |
| 药代特性 | 半衰期、长效/短效、服药时机要求、水溶/脂溶 |
| 副作用谱 | 各成员在主要副作用维度上的相对排序(而非只列通用清单),附真实发生率 |
| 特殊人群证据 | 族裔、老年、肝肾功能不全、孕哺等人群的专项证据 |

副作用写法上要对抗恐慌化:给出真实发生率、剂量依赖性、以及安慰剂对照下的归因证据(如他汀肌痛的反安慰剂效应),网络流传的说法如实分析而不是照搬或简单驳斥。

### 3. 机制层展开

把对比中用到的机制用大白话讲透(CYP450 是什么、为什么短效药要睡前吃、水溶脂溶意味着什么)。目的:让用户具备延伸判断能力,能理解后续医生说的话,而不是拿到一张只能死记的表。

### 4. 剂量与效果规律

- 查明该类药的**剂量-响应曲线形状**(他汀是"翻倍只多降 6%"的边际递减;别的类各有规律),据此评估加量的真实收益。
- 默认策略:**最低有效剂量起步**,观察响应再调。
- 剂量不够时,**联用不同机制的药往往优于继续加量**(如他汀+依折麦布),把该类的标准联用路径写成预案。

### 5. 族裔与人群证据加权(本技能最独特的一步)

- 查该族裔的**药代动力学差异**(如亚洲人服他汀的血药浓度约为白种人两倍,同剂量=更高暴露)。
- 查在该族裔人群中做过的临床试验与真实世界研究,**评估证据的"对口程度"**:一个在 1.3 万日本患者中做的结局试验,对中国用户的参考价值可能高于 2 万欧美白人的试验。
- 注意这一步可能**翻转默认结论**:西方视角下某药"证据薄"的短板,换到东亚画像可能反而是"证据更对口"的长板。
- 查该国/该地区指南的起始剂量建议与 FDA 标签的差异。

### 6. 画像驱动三档筛选

把全部成员分三档,**每一档都给理由**:

- **明确排除**:逐个写排除原因(与画像的具体冲突)。排除的也要出现在报告里——用户可能正在用其中某个,看到理由才有价值。
- **有条件考虑**:什么条件下值得回头考虑。
- **重点候选**:逐条对照用户的需求清单写"满足哪些、不满足哪些",不满足的不粉饰。最后给排序和每一名的理由。

不打分。药物选择的维度权重因人因病差异太大,伪装成分数会显得精确实则误导;逐条需求匹配让用户看得见推理,也方便医生反驳。

### 7. 落盘

报告固定结构(见下),另加一份**就诊讨论问题清单**:把调研中发现的、需要医生裁决的点写成可以直接带去诊室的问题(如"我的降脂响应强于平均,是否有减量到 2mg 的空间?")。

## 报告结构

保存为 Markdown 文件,文件名 `{调研对象}_选药调研.md`。当前版本只输出中文报告,专业术语与药名首次出现时附英文原文,如 匹伐他汀 (Pitavastatin)。

```
# {调研对象}选药调研
## 一、画像与诉求(模式B则写明面向通用人群)
## 二、全员盘点(表:成员/商品名/批准年/强度/代谢/长短效;含撤市成员)
## 三、关键规律(五维对比+机制讲解+剂量规律,按需要设小节)
## 四、族裔与人群证据
## 五、三档筛选(排除/有条件/重点候选,逐条需求匹配)
## 六、排序建议与联用预案
## 七、就诊讨论问题清单
## 八、参考文献(编号与正文 [n] 对应,附 URL)
## 免责声明
```

免责声明固定内容:本报告为信息调研,不构成医疗建议或处方;用药的开始、停止与剂量调整请务必与医生讨论决定。

## 证据与引用规则

- 来源优先级:官方药品标签(FDA label / DailyMed)与权威指南(如 AHA/ACC、ESC、各国学会指南)> PubMed 系统综述与大型 RCT > 权威医学科普(Mayo Clinic、NIH)> 其他。品牌营销内容不作为依据。
- 族裔证据要专门搜:`{药名} pharmacokinetics Asian`、`{药名} clinical trial Japan/China/Korea`、该地区指南名。
- 具体数字(发生率、降幅、半衰期、等效剂量)须有来源并用 [编号] 标注;基础药理常识可用自有知识,不标注但也不得伪装成引用。
- 找不到的信息写"未找到",不推测填充。

## 安全红线

- 不建议用户自行开始、停止或调整处方药;所有结论落在"与医生讨论"上。
- 不提供绕开处方获取处方药的途径;不推荐以不受监管的替代品替代处方药(如用红曲替代他汀——如实分析其风险即可)。
- 遇到提示急症的描述(胸痛、过敏反应等),先建议立即就医,调研退后。
- 网络恐慌类说法(某药"吃了就废")按证据拆解:真实发生率、选择偏差、反安慰剂效应,不放大也不敷衍。

## 输出前自检

- [ ] 全员盘点与权威清单核对过,撤市成员已列并给出原因
- [ ] 五个对比维度都覆盖,副作用附真实发生率
- [ ] 族裔证据专门检索过至少一轮(模式B也要,分人群写)
- [ ] 三档筛选:每个排除都有理由,每个候选都有逐条需求匹配
- [ ] 有联用预案与就诊讨论问题清单
- [ ] 引用编号与文献列表一一对应,数字都有来源
- [ ] 免责声明在,全文没有"你应该改成吃 X"式的处方式表述
