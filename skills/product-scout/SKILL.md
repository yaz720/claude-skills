# 实体产品选购深调 (Product Scout)

## 技能目标

把"我要买个 X"端到端变成"选定一个经过逐项核验的具体产品"。
覆盖一切**实体消费品**(个护/清洁/家具/家电/工具/数码/母婴/文具等);
不覆盖食品(→food-research)、补剂(→supplement-scout)、药品(→rx-scout)、服务商(→service-scout)。

## 核心信条(全流程贯穿,违反任何一条即翻车)

1. **来源分级**:带联盟链接的商业榜单("best XX 2026"、品牌博客)只能用来**收集候选名单**,
   **绝不作为推荐依据**;推荐依据只能是严格第三方评审 + 数据库 + 你自己逐项核对的成分/参数表。
2. **逐项核验**:推荐任何产品前,把它的**完整成分表 (INCI) 或规格表**拉出来逐项过一遍。
   没核过成分表的推荐不许出手。
3. **双重关卡**:认证/安全数据库(EWG 等)管的是**毒性**,不管**刺激性/温和度/体验**——
   两道关都要过。反面教材:EWG Verified 的产品用着 SLS 同类表活(Sodium Coco-Sulfate)。
4. **极简优先**:同等功能下成分/用料越少越好,每多一项就多一个致敏/故障/失效变量;
   识别并点名"故事性成分"(深海水、植物提取物点缀)与纯营销宣称。
5. **主功能优先 + 机制审查**:先明确品类的第一功能(洗发水=温和+安全+去污);附加卖点(蓬松、
   美白、静音)一律排第二,且**必须回答"靠什么机制实现"**——靠"不添加"实现的免费收下,
   靠低风险添加实现的如实标注,靠可疑添加或无证据宣称实现的**扣分**。
6. **够用即最优**:性能与需求匹配,超出需求的性能不是白送的——化学品类里过剩的清洁力
   全部转化为刺激,机械品类里过剩的功率/参数往往兑换成噪音、体积、价格。先问"多强才刚好够用户"。
7. **第一性原理拆解**:评价一个品类前先回答"它最少需要什么"——必需项清单在手,
   才能判断哪些成分/部件是核心、哪些是体验优化、哪些是凑数营销。

## 工作流程

### 第一步:需求画像

- 买什么?给谁用?(使用者的身体特征/使用环境常常翻转结论——发质、肤质、房间大小、噪音敏感)
- **这个品类对该用户的"主功能"是什么?**(用户常答不出,替 TA 拆:先问最不能妥协的是什么)
- 预算、购买渠道、品牌好恶
- 用户对安全/极简/环保各在意到什么程度(决定第 4-5 步的严格档位)

### 第二步:建立品类判断框架 ⚠️ 先造尺子,再量产品

搜集该品类的配方学/工程学常识,产出一张**判断框架表**:
- 核心机理:这个品类靠什么起作用?(洗发水=表活;净化器=CADR+滤网;椅子=支撑结构)
- **档位表**:关键成分/参数按"强弱×利弊"分档(如表活的刺激-去污四档表),并注明每档适合谁
- 第一性原理最小配置:必需项/可选项/营销项三栏
- 该品类已知的风险成分/缺陷设计与召回、诉讼史(如 DMDM hydantoin 之于洗发水)

**没有这张表就开始比产品 = 被参数表牵着走。**

### 第三步:来源分级搜索

按 `references/source-tiers.md` 的分级与品类数据库地图执行。红线:

- 商业榜单只进候选池;候选池宽进(8-12 个),核验严出
- 优先严格第三方(Consumer Reports、MadeSafe 合作评审、RTINGS、Project Farm 类实测)
- 成分/参数数据库(EWG Skin Deep、INCIDecoder、CosDNA、规格库)用于逐项核验
- 学术综述/临床研究用于机理与安全争议(诉讼史搜 "class action"/"recall")

### 第四步:逐产品核验(候选池 → 短名单)

对每个候选:
1. 拉**完整成分表/规格表**(数据库或官网,不是转述)
2. 对着第二步的档位表逐项归档:核心成分在哪档?有无风险名单成员?
3. **两道关**:安全认证过了吗?温和性/适用性过了吗?(各自独立判)
4. 极简度:总项数、故事性成分数、香精/致敏源
5. 宣称 vs 数据:官方"宣称"(pH balanced)与"公布数值"(pH 5.0-5.5)**区别对待**,
   宣称要如实标注"未公布数值",可给用户自验方法(试纸/分贝计/功率计)

### 第五步:附加卖点机制审查

对短名单产品的每个卖点(蓬松/抗菌/静音/速干…)逐个问"**靠什么实现**",三类判决:
- **靠"不添加"/靠基本设计实现** → 免费收下,加分
- **靠低风险添加实现**(成膜聚合物、水解蛋白) → 如实标注"有效但有残留/有代价",中性
- **靠可疑添加或无证据宣称**(冲洗型产品里的生物素"强韧发根") → 扣分,点名是营销

### 第六步:报告产出

落盘 Markdown 报告并发给用户,结构:
1. **Executive Summary**:品类核心判断标准 + Top 推荐 + 最大的坑
2. **针对性建议**(对着用户画像)
3. **判断框架**(第二步的档位表,让用户以后自己也会挑)
4. **争议澄清**:该品类流传的迷思逐条对证据(如"硫酸盐致脱发"无证据、真涉诉的是 DMDM)
5. **机制审查结果**(第五步)
6. **推荐名单**:每条注明验证来源(数据库链接);短板如实写
7. **明确不推荐/降级名单及理由**——和推荐同等重要,尤其"看起来很对但核出问题"的
   (认证掩盖强刺激、贵价不换温和)
8. **信息来源**:按"严格第三方/数据库、学术临床、诉讼召回、机制"分组列链接

### 第七步:追踪与迭代

- 主动提议在报告尾部加**产品追踪表**(价格、链接、试用笔记),后续对话持续维护
- 用户试用反馈(好用/翻车)收进报告;方法论级翻车(某来源不可靠、某档位判错)
  → 用 skill-forge 的 harvest 收进本技能 evals

## 注意事项

- **敢于推翻自己**:核验结果与初版推荐冲突时,降级/撤回并明说原因(v1 靠榜单推了 SLES 贵价款,
  v2 核成分后公开降级——这个动作本身就是可信度)
- **中文回复,专业术语附英文原文**(INCI 名、认证名)
- 不替用户下单;价格标"参考价,以购买时为准"
- 医疗宣称红线:产品若涉治疗功效(药用去屑、防脱),给临床证据档位但不做诊疗建议;
  持续性健康问题指向就医(→care-scout)
- 搜索查询不带用户个人身份信息
