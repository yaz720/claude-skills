# nutrition-analyzer — 食物营养成分分析技能

> **状态:🚧 开发中**(触发基线 26/26 通过、负例全过;能力用例 cap-001 按修订后规格实跑 12/12 通过,
> 另 3 条仍待真实产出,补齐后再转 ✅)

一个用于 Claude 的 **Skill**,把「一组食材 / 一份食谱 / 一张营养标签照片 / 一张成品菜照片」变成一份**可保存的营养报告**,而不只是在对话里报一个热量数字。

## 这个技能做什么

- **四种输入通道**:营养标签照片(OCR 提数)、文字配料表(中英混合/单位混合都认)、只给名称走 USDA 估算、只给一张成品菜照片走视觉估算(带尺寸锚点,先请用户确认清单再算)
- **单位标准化**:内置常用 cup/oz/lb/tbsp → g 换算表
- **逐原料营养贡献表**:每种原料各贡献多少热量/脂肪/碳水/蛋白质,来源(标签 vs 估算)逐项标注
- **可选原料对照**:食谱里"可选/optional"的原料单独标注,JSX 里可切换,PDF 里并排给"含/不含"两版合计与每份数值
- **两张解读卡片**:营养亮点(只列 %DV ≥20% 的项并注明主要来自哪个原料,没有就如实说没有)+ 糖分构成(三档:总糖少就省略、单一糖占九成以上收成一句话、构成真复杂才画进度条)
- **视觉主题**:按食材自动选主题 Emoji + 柔和渐变背景(16 类 emoji × 8 个色系对照表)
- **FDA 标准 Nutrition Facts 标签**:黑白高还原,%DV 按 2000 kcal 基准
- **三格式交付**:React 交互式 artifact / US Letter PDF 真文件(Playwright 渲染,禁止 reportlab 画坐标,防表格跨页截断) / 对话内文字明细表

## 报告按输入伸缩

不是每次都出五段。单一食材(如"甜樱桃 100g")只出 主题头 + FDA 标签 + 两张解读卡片;有原料无做法出 1/2/4/5;完整食谱含步骤才五段齐全。**不生造空板块**。

板块顺序是 **结论在前、过程在后**:FDA 标签(第 4 部分)排在各原料营养贡献明细表(第 5 部分)之前——多数人翻报告只想看"这一份吃进去什么",不该让每个人先趟一遍推导。

## 双语规则(红线)

FDA 标签**正文恒为英文**——"Nutrition Facts"、"% Daily Value"、"Total Fat" 是法定格式的一部分,译成中文就不再是"高度还原 FDA 标签"。中文以小号副标并排。双语切换只切标签**之外**的内容。

## 血统(为什么这版叫"合并版")

本技能早期在 claude.ai 上散装迭代,分叉成两条并行分支,前 107 行完全相同、之后完全分道:

- **「食谱报告」分支**(2026-05-09,桃酥饼干那次):五段式报告 + 可选原料标注与切换 + 做法步骤提取
- **「糖分+主题」分支**(甜樱桃那次):糖分构成拆解 + 主题 Emoji/背景色系统 + 三格式默认交付 + Playwright 完整模板与 reportlab 禁令

收编进本库时把两条分支合并,并补上两版都没写进文档、但实际产出里出现过的**中英双语切换**(同时定下"FDA 标签不译"的红线)与**糖分百分比必须写出数字**两条。

合并版首次实跑后又按使用反馈修订了一轮:标签前置于明细表、徽章去 emoji 且必须同时给每份与整批热量、同源来源合并成表下一句脚注、新增营养亮点卡承接微量营养素、糖分卡改三档、不提没有出处的"原方"。
