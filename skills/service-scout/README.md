# service-scout(寻商)

> **状态:🚧 开发中**(触发基线 22/22 一把过、负例全过;能力用例 3 条待首跑实测,补齐后再转 ✅)

一个 Claude Code **技能**:把「我要找个本地服务商」(驾校、家教、搬家、修车、装修……)
变成「选定合适的一家/一位并联系上」的端到端甄别流程。

与 [care-scout(寻医)](../care-scout/) 同源的方法论,剥去医疗专属部分后泛化到一切
**雇人提供服务**的场景。裸问模型也能搜出几家店名,但它**不会自己做**的是:

- **行业情报先行**:先建立这一行的内行常识——要不要州执照、定价套路是什么、
  高发坑在哪(驾校拖课时、搬家低报高收、修车小病大修、装修收定金消失),
  带着坑去读评价,而不是泛泛看星级
- **Yelp/Google 双平台交叉解读**:两平台机制不同(过滤器、刷评难度、用户群),
  分数并列不平均;刷评识别信号;3 星评价与最新 10 条优先读
- **负面评价按主题归类**:隐性加价|爽约改约|态度差|结果差|售后失联,
  区分偶发与模式、针对个人与针对机构——教学类服务盯"人"不盯"店"
- **资质与投诉核验**:州执照库(DMV/CSLB/BAR/FMCSA…)、BBB 投诉处理记录、营业年限交叉验证
- **中英双语询价话术**:必问清单 + 联系阶段红旗(只收现金、拒书面报价、催单施压)

## 这个技能做什么

- 需求画像(给谁用、预算、时间、语言、对"人"的偏好)→ 多渠道搜索(中英文关键词都搜)
- 候选池 8-12 家 → 评价交叉解读 + 资质核验淘汰 → 推荐 3-5 家,负评分析单独列
- 每家给出:资质状态、双平台评分并列、正负评价提炼、价格信号、匹配度说明
- 附可直接用的询价/比价话术与备选方案

## 边界

- **不覆盖医疗从业者**(医生、PT、针灸、有康复背景的教练)→ [care-scout](../care-scout/)
- **不覆盖买实体商品选牌子** → product-research
- 不覆盖餐厅/景点这类一次性消费推荐;不回答纯知识问答(如何倒车入库、怎么换机油)
- **不替用户下单、付款、签约**——话术给到位,最后一步用户自己来
